1. Übersicht

CMDSolver löst nichtlineare Gleichungssysteme F(x) = 0, F: ℝn→ℝn, durch iterative Newton-artige Verfahren. Eingabe über CAS-Dateien mit symbolischen Gleichungen, Variablen-Bounds, INITIALIZE-Blöcken und konditionalen IF/ELSE-Ausdrücken.

Stand Mai 2026 — Version 2.3: 7 Solver vollständig implementiert und getestet. Neu in v2.3: BROYDEN_SPARSE (Broyden + GSPAR-LU via Sherman-Morrison-Woodbury), automatischer Solver-Test via -TEST Flag, paralleler thread-sicherer Jacobi-Aufbau (O(nnz)).

3. AbstractSolver — Gemeinsame Infrastruktur

3.1 Jacobi-Aufbau (thread-sicher, O(nnz))

Pseudocode — buildJacobian

// AbstractSolver.buildJacobian() — v2.3

// Mapping einmalig aufbauen (read-only für Threads)
fullToReduced = new int[totalCount]
reduced = 0
for j = 0..totalCount-1:
  if var[j].isFixed(): fullToReduced[j] = -1
  else:               fullToReduced[j] = reduced++

// Parallel über alle Gleichungen
IntStream.range(0, n).parallel().forEach(i ->

  row = new double[functionCount]  // thread-lokal!

  if symbolisch AND NOT CALL:
    for idx in eqn.getVariableIndices(values):
      rc = fullToReduced[idx]
      if rc >= 0:
        row[rc] = derivMat[i][idx].evaluate(values)

  elif CALL-Gleichung:
    for k in indices:
      rc = fullToReduced[indices[k]]
      if rc >= 0: row[rc] = eqn.calcDeriv(values, k)
    // Output-Variable: dF/dOutput = +1
    row[fullToReduced[indices[0]]] = 1.0

  else: // Finite Differenzen (Homotopie)
    localValues = new HashMap(values)  // thread-lokale Kopie!
    f0 = eqn.calcFunc(localValues)
    for j = 0..totalCount-1:
      rc = fullToReduced[j]
      if rc < 0: continue  // fixiert — überspringen
      h = max(1e-6·|xj|, 1e-8)
      localValues[alias] = xj + h
      row[rc] = (eqn.calcFunc(localValues) - f0) / h
      localValues[alias] = xj

  // Thread-sicher: jeder Thread schreibt in eigene Zeile i
  for rc = 0..n-1: a[i][rc] = row[rc]
)
CALL-Gleichungen: F = Output − pCALL(inputs) = 0. Die Output-Variable hat immer Koeffizient +1 — wird explizit gesetzt, da calcDeriv(values, 0) für sie 0 zurückgibt.

3.2 Stagnations-Restart

Wenn fsum sich über 8 aufeinanderfolgende Iterationen weniger als 1% verbessert, werden alle freien Variablen um ±2.5% gestört (deterministisch, Seed = Iterationsnummer):

if improvement < 1%  für 8 Iterationen:
  rng = new Random(iteration)           // reproduzierbar
  for jede freie Variable:
    val += val * 0.05 * (rng.nextDouble() - 0.5)   // ±2.5%
  evaluateF() → fsum neu
  stagnCount = 0

5. Solver im Detail

5.1 Newton-Armijo (-S:NEWTON_ARMIJO)

Klassisches Newton-Raphson mit dichter Gauss-Jordan-Inversion (MatrixSimple.inverse(), O(n³)) und Armijo-Backtracking. Konditionszahl wird per Frobenius-Norm geschätzt.

ParameterFlagDefaultBeschreibung
Startvektordump-DV:<file>—Startwerte vor Iter 0 im -U-Format
Wann: Standard für n < 200. Quadratische Konvergenz nahe der Lösung.

5.2 Newton-GSPAR (-S:NEWTON_SPARSE)

Newton mit GSPAR sparse LU (Grund, WIAS Berlin ~1994). Löst J·dx = −F in O(nnz·fill) statt O(n³). Einmalige Strukturanalyse, schnelle Refaktorisierung via Pseudo-Code.

ParameterFlagDefaultBeschreibung
Reset-Intervall-SB:RESET=n1Alle n Iter vollständig re-faktorisieren
Kappa-Reset-SB:KAPPA=x1e12κ-Schwelle für erzwungene Refaktorisierung
Wann: n > 200, dünn besetzte Jacobi (nnz ≪ n²). 2–3× schneller als Newton-Armijo.

5.3 Newton-GSPAR+Armijo (-S:NEWTON_SPARSE_ARMIJO)

Erbt GSPAR-LU-Kern (extends GSPARSolver) und ergänzt Armijo-Liniensuche. Alle GSPAR-Parameter plus Armijo-Backtracking.

Wann: Große Systeme mit schlechten Startwerten — GSPAR-Effizienz + Armijo-Robustheit.

5.4 Levenberg-Marquardt (-S:LEVENBERG_MARQUARDT)

Löst (JTJ + μ·D)·dx = −JTF mit adaptivem μ. D = diag(JTJ). μ-Initialisierung via geometrisches Mittel (verhindert Einfrieren durch einzelne große Jacobi-Einträge).

ParameterKonfigDefaultBeschreibung
μ-InitlmMuInit1e-6μ₀ = lmMuInit · geomMean(diag(JᵀJ))
μ-VerkleinerunglmNuDown5.0μ /= nuDown bei Fortschritt (ρ > 0.25)
μ-VergrößerunglmNuUp2.0μ *= nuUp bei Stagnation
Gain-RatiolmRhoMin0.25Schritt akzeptiert wenn ρ > lmRhoMin
Wann: Schlecht konditioniert (κ > 10¹²), Ma→1-Übergänge, stark nichtlinear.

5.5 Broyden (-S:BROYDEN)

Aktualisiert J per Rang-1-Update. Adaptiver Checkpoint/Rollback: bei Divergenz (fsum > 2×ckFsum) zurücksetzen + Intervall halbieren. Nach 3 Rollbacks: Newton-Fallback.

ParameterFlagDefaultBeschreibung
Reset-Intervall-SB:RESET=n1Jacobi alle n Iter neu. 10 = adaptiv
Kappa-Reset-SB:KAPPA=x1e12κ-Schwelle für erzwungenen Reset
Warmstart-Schwelle-SB:WARMKAPPA=x1e8κ für Jacobi-Wiederverwendung beim Reset
Wann: Teurer Jacobi-Aufbau (viele CALL-Gleichungen), aber n klein.

5.6 Broyden-GSPAR (-S:BROYDEN_SPARSE)

Kombiniert Broyden-Rang-1-Updates mit GSPAR-LU als Basislöser. Statt dense Gauss-Jordan-Inversion löst GSPAR das LGS in O(nnz·fill). Broyden-Korrekturen werden via sequentieller Sherman-Morrison-Woodbury angewendet.

MethodeLGS pro IterJacobi-Speicher
Broyden (dense)O(n³)O(n²)
Broyden-GSPARO(nnz·fill + bCount·n)O(nnz + bCount·n)
ParameterFlagDefaultBeschreibung
Reset-Intervall-SB:RESET=n1GSPAR re-faktorisiert alle n Iter
Kappa-Reset-SB:KAPPA=x1e12κ-Schwelle für erzwungenen Reset
Wann: Große Systeme (n > 200) wo Broyden-Updates die GSPAR-Effizienz ausnutzen. Konvergiert auf SimpleSystem in 3 Iterationen — identisch zu Newton-GSPAR.

5.7 Homotopie (-S:HOMOTOPY)

Löst H(x,t) = (1−t)·J₀·(x−x₀) + t·F(x) = 0 für t: 0→1. Prediktor–Korrektor-Schema mit adaptiver Schrittweite.

ParameterFlagDefaultBeschreibung
Schritte-SH:STEPS=n10Initiale Anzahl Homotopie-Schritte
Bogenlänge-SH:DS=x0.1Initiale Schrittweite ds
Innerer Solver-SH:INNER=typNEWTON_ARMIJOKorrektor-Solver pro Schritt
Ma=1-Preset-SH:CRITICAL50 Schritte, ds=0.02
Wann: Wenn alle anderen Solver divergieren — schlechte Startwerte, Bifurkationspunkte.

6. Newton-GSPAR intern

6.1 Gesamtablauf

Pseudocode — Hauptschleife

// AbstractSolver.solve()
initStructSwitches(sysData)
InitGuessApplier.apply(sysData)

while ‖F(x)‖ > tol AND iter < maxIter:

  // Jacobi parallel aufbauen (v2.3)
  buildJacobian(a, sysData, values)
  if scalingActive: scaleJacobian(a, D)

  // GSPARSolver.computeStep()
  if NOT structureAnalyzed:
    analyzeStructure(sysData, n)
    structureAnalyzed = true

  fillJacobiValues(a, n)
  // Werte aus a → Pattern → sparseA.a

  if iter==0 OR needsRefactorize(kappa):
    GSPAR.factorize(sparseA, workspace)
  else:
    // schnelle Refaktorisierung via Pseudo-Code
    sparseA.transferValues(jacobiVals, ws.af)

  dx = GSPAR.solve(workspace, −F)

  // AbstractSolver (nach computeStep)
  dxOrig = unscaleStep(dx)   // D · dx_skaliert
  alpha  = armijoStep(dxOrig, F, x)
  x += alpha · dxOrig
  PhysicalProjector.project(x)

  F(x) → fsum; iter++

6.2 Super-Pattern für IF/ELSE-Gleichungen

Kernproblem: Bei IF/ELSE-Gleichungen ändert sich das Jacobi-Sparsity-Pattern zwischen Iterationen. Ein festes Pattern aus Iter-0 führt zu falschen LU-Zerlegungen → Divergenz. Lösung: Super-Pattern = Vereinigung aller möglichen Nicht-Null-Positionen beider Zweige.

Pseudocode — analyzeStructure

// GSPARSolver.analyzeStructure(sysData, n)

// 1. Mapping vollständiger Index → Jacobi-Spalte
fullToReduced = new int[totalCount]
reduced = 0
for j = 0..totalCount-1:
  if var[j].isFixed(): fullToReduced[j] = -1
  else:               fullToReduced[j] = reduced++

// 2. Super-Pattern: Vereinigung IF+ELSE
pattern = new boolean[n][n]
for row = 0..n-1:
  eqn = sysData.getEqnAtIndex(row)
  colSet = eqn.getVariableIndices()  // IF-Zweig

  if eqn.isConditional()
  OR eqn.isStructConditional():
    elseIdx = eqn.getConditionalElseEqn()
                 .getVariableIndices()
    colSet.addAll(elseIdx)  // Vereinigung!

  for fullCol in colSet:
    rc = fullToReduced[fullCol]
    if rc >= 0: pattern[row][rc] = true

// 3. Allokation
sparseA   = SparseMatrix.buildFromTriplets(pattern)
workspace = GSPAR.allocate(sparseA)
jacobiVals = new double[nnz]
structureAnalyzed = true  // nie wieder!

Pseudocode — fillJacobiValues

// Pro Iteration — O(nnz)
k = 0
for i = 0..n-1:
  for je = sparseA.ia[i]..sparseA.ia[i+1]-1:
    j = sparseA.ja[je]     // Spalte aus Pattern
    jacobiVals[k++] = J.getValueAt(i, j)
    // 0.0 wenn Zweig inaktiv — korrekt!

6.3 GSPAR LU-Faktorisierung (PAQ = LU)

Pseudocode — LU-Faktorisierung

// GSPAR.factorize(sparseA, ws)

// ① dllugc — Matrix in Workspace
ws.af   = copy(sparseA.a)
ws.jlu  = copy(sparseA.ja)
ws.jzei = copy(sparseA.ia)

// ② dllugb — LU mit MIN_FILL Pivoting
for k = 0..n-1:
  pivotCol = argmin fillCount(j≥k)
  ws.ip[k] = pivotCol
  pivot = ws.af[diagonal(pivotCol)]
  for i mit af[i,pivotCol] ≠ 0:
    factor = af[i,pivotCol] / pivot
    af[i,:] -= factor * af[pivotCol,:]
    // JLU: Pivot → -(col+1)

// ③ dllugd — Verkettung für Zugriff
for i = 0..n-1:
  ws.iu[i] = erste U-Position in Zeile i
  ws.il[i] = erste L-Position in Zeile i

// ④ dldsp1 — Pseudo-Code für Refaktorisierung
// ic[k] = (IE2 << 16) | IE1
// Fortran RSHIFT ≡ Java >>> 16

// ⑤ dlsolk — Lösung
// Vorwärts:  L·y = b[IP]  (Permutation!)
// Rückwärts: U·dx = y

Pseudocode — Pseudo-Code-Interpreter

// dldint — schnelle Refaktorisierung
while L < ICEN:
  ENT = ic[L]; L += 2
  ie2 = ENT >>> 16
  ie1 = ENT & 0xFFFF

  S = 0
  for k=0..ie1-1:
    S += af[ic[L]] * af[ic[L+1]]; L+=2

  switch ie2:
    1: af[ic[L]] -= S   // U-Element, alt
    2: af[ic[L]]  = -S  // U-Element, neu
    3: af[ic[L]]  = S   // Pivot
    4: af[ic[L]] -= S   // L-Element, alt
    5: af[ic[L]]  = -S  // L-Element, neu
    6: L++              // Sonderfall

6.4 Armijo-Liniensuche

Kritische Architektur: Armijo läuft nach unscaleStep(dx) — immer im physikalischen Raum (Pa, K, kg/s). Frühere Versionen führten Armijo im skalierten Raum durch → falsche Schritte bei -SC:DIAGONAL (Bug B19). 
// AbstractSolver.solve() — Schritt-Architektur
dx     = computeStep(J, f, …)       // GSPAR: reiner LU-Solve
dxOrig = unscaleStep(dx)            // physikalischer Raum: D · dx_skaliert
alpha  = armijoStep(dxOrig, f, x)   // suche alpha ∈ {1, ½, ¼, …}
x += alpha · dxOrig

// armijoStep — Sufficient Decrease Bedingung
f0 = ‖F(x)‖²;   slope = -f0   // Newton-Abstiegsrichtung
alpha = alphaInit  // 1.0
while alpha > alphaMin:
  xTry = x + alpha · dxOrig
  fTry = ‖F(xTry)‖²
  if fTry ≤ f0 + c₁ · alpha · slope: break
  alpha *= rho   // 0.5

11. Startwert-Diagnose (-DI)

  1. Residuums-Diagnose: F(x₀) — Top-10 größte Residuen
  2. Bounds-Qualität: val=lo=0 → geometrisches Mittel (√(hi·0.1))
  3. Propagations-Init: y = f(x_fixed) direkt auswerten → Startwert setzen
  4. Sensitivitäts-Check: Jacobi-Spalten nahe Null → mögliche Redundanz
-DI setzt useInitData=false — InitGuessApplier läuft nicht nochmals.

Thread-Safety

Der Jacobi-Aufbau in buildJacobian() ist intern thread-sicher (parallele Zeilen via ForkJoinPool). Die Solver-Objekte selbst haben jedoch mutablen Zustand (LM: μ, Broyden: bU/bV, GSPAR: workspace) — für parallele Ausführung mehrerer Betriebspunkte muss jeder Thread eine eigene Solver-Instanz verwenden. freshRunData() im -TEST-Modus stellt das sicher.

16. Entwicklungshistorie

Phase 1 — Monolithischer Solver

Einzelne EqnSystem.java, gedämpftes Newton ohne Liniensuche.

Phase 2 — Modularisierung und AbstractSolver

Strategy-Pattern: AbstractSolver, SolverConfig, SolverFactory. PhysicalProjector, VariableScaler.

Phase 3 — LM, Broyden, Homotopie

Levenberg-Marquardt, Broyden (adaptiv, Checkpoint/Rollback), Homotopie (Arc-Length, -SH:CRITICAL).

Phase 4 — Batch-Mode und InitialValueAnalyzer

CSV-Batch-Mode, BatchRunner, -DI Flag.

Phase 5 — INITIALIZE-Block Fix

initStructSwitches() Reihenfolge, parseStructIfCondition() Bug B1–B3.

Phase 6 — GSPAR Sparse-LU (Fortran → Java)

Vollständige Portierung GSPAR (F. Grund, WIAS Berlin ~1994). Super-Pattern, JLU-Kodierung, Bugs B12–B20. 2.4× Speedup gegenüber Newton-Armijo bei n=623.

Phase 7 — LM-Stabilisierung und Homotopie-Fix (v2.1)

LM: geometrisches Mittel für μ-Init. Homotopie: hValues-Datenfluss fix (B21). Newton-Armijo als Default-innerer-Solver. Stagnations-Restart.

Phase 8 — Thread-sicherer Jacobi + NEWTON_SPARSE_ARMIJO (v2.2)

afull eliminiert, buildJacobian parallel + thread-sicher (B24). CALL-Output-Fix (B22). Neuer Solver NEWTON_SPARSE_ARMIJO (extends GSPARSolver + Armijo).

Phase 9 — BROYDEN_SPARSE + -TEST Modus (v2.3)

Neuer Solver BROYDEN_SPARSE: Broyden-Updates auf GSPAR-LU via Sherman-Morrison-Woodbury. Konvergiert in 3 Iterationen (identisch Newton-GSPAR). Automatischer Solver-Test via -TEST Flag: alle 7 Solver sequenziell, frische SystemData-Kopie pro Run, Ausgabe _solvertest.txt.

18. Mögliche Erweiterungen

Phase 2 — LM und Broyden vollständig sparse

LM: JTJ sparse aufbauen — bei dünnbesetzter Jacobi bleibt JTJ oft noch handhabbar. Broyden dense: dense J₀ durch GSPAR-LU ersetzen (analog BroydenGSPARSolver).

NEWTON_SPARSE_ARMIJO als Homotopie-innerer-Solver

Aktuell verwendet Homotopie Newton-Armijo (dense). Bei n>200: -SH:INNER=NEWTON_SPARSE_ARMIJO würde erheblichen Speedup bringen.

GMRES für sehr große Systeme

Für n>5000 mit ILU-Präkonditionierung. computeStep() in AbstractSolver ist solver-agnostisch — GMRES überschreibt nur diese Methode.

Homotopie-ITER Fix im -TEST Modus

HomotopyResult enthält keine ITER-OutputVariable im selben Format wie DirectSolver. Fix: HomotopyResult.totalIterations als ITER-Wert in solution-Liste eintragen.

Adaptive Solver-Auswahl

if kappa < 1e8:    NEWTON_SPARSE (schnell)
if kappa < 1e14:   NEWTON_ARMIJO (robust)
if kappa ≥ 1e14:   LEVENBERG_MARQUARDT (stabil)
