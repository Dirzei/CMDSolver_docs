Dateistruktur — Überblick

Eine CAS-Datei besteht aus mehreren Sektionen die in beliebiger Reihenfolge auftreten können. Der Parser ist case-insensitiv — Schlüsselwörter können groß oder klein geschrieben werden.

// ── Sektion 1: Prozedurendeklaration ────────────────── PROCEDURE prozedurName CALL: BUILT_IN_FUNCTION_NAME; INPUTS: REAL, REAL, ...; OUTPUTS: REAL; END // ── Sektion 2: Variablendeklaration ─────────────────── VARIABLE VARIABLENNAME LOWER: 0.0; VALUE: 100.0; UPPER: 500.0; UNIT: "Pa"; END // oder Kurzschreibweise: NAME.SUBNAME AS REAL (Description: "Text", Lower: 0, Value: 1, Upper: 10, Spec: Fixed, Unit: "m"); // ── Sektion 3: Startwert-Overrides ──────────────────── INITIALIZE VAR = 123.4; VAR.Lower = 0.0; VAR.Upper = 500.0; ENDINIT // ── Sektion 4: Gleichungen ──────────────────────────── VAR_A = VAR_B * 2.5 + SQRT(VAR_C);
Parsing-Reihenfolge: Der Parser liest die Datei zweimal — erst werden alle Variablen und Prozeduren erfasst, dann werden die Gleichungen interpretiert. Die physische Reihenfolge in der Datei spielt für den Parser keine Rolle.

Variablendeklaration

Langform — VARIABLE Block

Syntax — VARIABLE Block
VARIABLE PARTM.F060.PT LOWER: 1000.0; VALUE: 196273.07; UPPER: 300000.0; UNIT: "Pa"; END

Kurzform — AS REAL Inline-Syntax

Syntax — AS REAL (empfohlen für moderne Modelle)
PARTM.F060.PT AS REAL ( Description: "Total pressure at station 060", Lower: 1000.0, Value: 196273.07, Upper: 300000.0, Spec: Fixed, Unit: "Pa", Latex: "P_{T,060}" );

Variablennamen — QNAME-Konvention

CMDSolver unterstützt Mehrfach-Punkt-Namen (Qualified Names) für hierarchische Modellstrukturen. Der Punkt ist kein Operator sondern Teil des Namens:

PARTM.F060.PT ← gültiger Variablenname (keine Operatoren) GLOBAL.PIVALUE ← hierarchisch: Modul.Variable GEOM.RJETPIPE ← hierarchisch: Bereich.Größe AMB.PS ← hierarchisch: Station.Größe
Bugfix B27/B28 (v2.3): Bounds-Overrides im INITIALIZE-Block für Mehrfach-Punkt-Namen werden korrekt via lastIndexOf('.') extrahiert. PARTM.F060.PS.Upper = ... setzt korrekt den Upper-Bound von PARTM.F060.PS.

Array-Variablen

Array-Deklaration
ARRAY_VAR[5] AS REAL (Value: 0.0, Spec: Free, Unit: "m"); // Erzeugt: ARRAY_VAR[0], ARRAY_VAR[1], ..., ARRAY_VAR[4]

INTEGERPARAMETER — Konstante (neu in v2.10)

INTEGERPARAMETER definiert eine ganzzahlige Konstante die beim Parsing als Präprozessor-Macro überall im Modell substituiert wird — in Arraygrenzen, FOR-Schleifen und Gleichungen.

INTEGERPARAMETER Syntax
// Deklaration NSTAGES AS INTEGERPARAMETER (5); // Verwendung in Array-Deklaration STAGE_TEMP[NSTAGES] AS REAL (Value: 300, Spec: Free, Unit: "K"); // Verwendung in FOR-Schleife FOR (i = 0:NSTAGES) STAGE_TEMP[i] = T_INLET - i * DELTA_T; END // Verwendung in Gleichungen TOTAL_STAGES = NSTAGES * 1.0; // wird zu: TOTAL_STAGES = 5 * 1.0
Substitution: INTEGERPARAMETER werden als Wortgrenzen-sicheres Macro substituiert — NSTAGES_OLD wird nicht verändert wenn NSTAGES definiert ist.

INITIALIZE Block

Der INITIALIZE-Block überschreibt Startwerte, Lower- und Upper-Bounds nach dem initialen Parsing. Er wird nach der Variablendeklaration ausgewertet — nützlich um Bounds dynamisch aus anderen Variablen zu berechnen.

INITIALIZE Block Syntax
INITIALIZE // Startwert setzen PARTM.F060.PS = AMB.PS * 1.5; // Lower-Bound überschreiben PARTM.F060.PS.Lower = AMB.PS * 0.5; // Upper-Bound überschreiben PARTM.F060.PS.Upper = AMB.PS * 4.5; // Konstante GLOBAL.PIVALUE = 3.14159265358979; ENDINIT
Auswertungsreihenfolge: INITIALIZE-Ausdrücke werden in Dateireihenfolge ausgewertet. Spätere Zeilen können frühere überschreiben. Expressions auf der rechten Seite können andere Variablen referenzieren — deren Werte stammen aus der Variablendeklaration.

PROCEDURE — Built-in Funktionen einbinden

Prozeduren verbinden CAS-Variablen mit den thermodynamischen Built-in Funktionen aus BIfunctions.java. Die Deklaration definiert Eingang und Ausgang; der Aufruf erfolgt über CALL.

Prozedur-Deklaration + Aufruf
// Deklaration (am Dateianfang) PROCEDURE pCPOFT CALL: CPOFTNOZ; ← Name der BIfunction INPUTS: REAL, REAL, REAL; OUTPUTS: REAL; END // Verwendung im Gleichungsteil CALL(PARTM.F060.CP) = pCPOFT(PARTM.F060.TT, PARTM.F060.WGR, PARTM.F060.FAR);
Prozedur-SchlüsselwortBedeutung
PROCEDURE nameBeginnt Prozedurendeklaration
CALL: FUNCNAME;Name der Built-in Funktion (aus BIfunctions)
INPUTS: REAL, REAL, ...;Anzahl und Typ der Eingaben
OUTPUTS: REAL;Anzahl und Typ der Ausgaben (aktuell nur 1)
ENDBeendet Prozedurendeklaration

Gleichungen

Grundform

Jede Gleichung hat die Form LHS = RHS; und wird vom Parser in die Residuumsform LHS − (RHS) umgewandelt. Das Semikolon am Ende ist obligatorisch.

Gleichungs-Beispiele
// Einfache Gleichung PARTM.F060.GAMMAT = PARTM.F060.CPT / (PARTM.F060.CPT - PARTM.F060.RGAS); // Mit mathematischen Funktionen PARTM.F060.Q = PARTM.F060.W * SQRT(PARTM.F060.TT) / PARTM.F060.PT; // Potenz PARTM.F060.PS = PARTM.F060.PT * (1 - (PARTM.F060.GAMMAT - 1) / 2) ^ EXP1; // CALL-Gleichung (Built-in Funktion) CALL(PARTM.F060.CP) = pCPOFT(PARTM.F060.TT, PARTM.F060.WGR, PARTM.F060.FAR);

Residuumsform

CAS-Gleichung: X = A * B + C;
Residuumsform: F(x) = X − (A * B + C)
Solver-Ziel: F(x) = 0 → X = A * B + C ✓

Kontrollstrukturen

IF / ELSE / ELSEIF / ENDIF

IF-Block Syntax
IF (VAR_A > 0.5) RESULT = VAR_A * 2.0; ELSE RESULT = VAR_A * 0.5; ENDIF // ELSEIF — wird durch Pre-Processing expandiert IF (MODE == 1) OUT = IN_A; ELSEIF (MODE == 2) OUT = IN_B; ELSE OUT = IN_C; ENDIF
ELSEIF-Expansion (v2.3): ELSEIF wird durch Pre-Processing in verschachtelte IF/ELSE-Blöcke expandiert. Mehrfaches ELSEIF ist möglich.

Struktureller IF — VAR.SPEC Bedingung

Eine spezielle IF-Form wertet den Status (Fixed/Free) einer Variable zur Parse-Zeit aus — nicht zur Laufzeit. Das erlaubt unterschiedliche Gleichungsstrukturen je nach Modellkonfiguration:

Struktureller IF (VAR.SPEC)
IF (GLOBAL.STATICSWITCH.SPEC == FIXED) // Diese Gleichung gilt wenn STATICSWITCH fixiert ist PARTM.F080.PS = PARTM.F060.PS; ELSE // Diese Gleichung gilt wenn STATICSWITCH frei ist PARTM.F080.PS = PARTM.F060.PS * GLOBAL.STATICSWITCH; ENDIF

FOR — Array-Expansion

FOR-Schleife
FOR (i = 0:4) ARRAY_VAR[i] = BASE_VAR * (i + 1); END // Expandiert zu 5 Gleichungen: ARRAY_VAR[0]=..., ARRAY_VAR[1]=..., etc.

Mathematische Funktionen

Diese Funktionen können direkt in Gleichungen verwendet werden. Sie werden vom Parser in CASprzak-Syntax übersetzt und symbolisch differenziert. Reihenfolge in der FUNC_MAP garantiert korrekte Übersetzung (längere Matches vor kürzeren).

Sonderfunktionen — binäre Expansion (neu in v2.10)

CAS-SyntaxExpansionHinweis
SQR(x) (x)^2 Quadrat — überall differenzierbar
MIN(a,b) 0.5*(a+b-ABS(a-b)) Knick bei a=b — Newton kann dort langsamer werden
MAX(a,b) 0.5*(a+b+ABS(a-b)) Knick bei a=b — Newton kann dort langsamer werden
MIN/MAX Alternative bei Newton-Problemen: Bei Konvergenzproblemen an der Knickstelle glattere Approximation verwenden: MIN(a,b) ≈ 0.5*(a+b-SQRT((a-b)^2+0.001))

Vollständiges Beispiel — Düsensegment

Beispiel: Isentrope Düsenströmung (vereinfacht)
/* Isentrope Düsenströmung — vereinfachtes Segment Unbekannte: PS, GAMMA, CP (3 Gleichungen, 3 Unbekannte) */ // ── Prozedurendeklaration ───────────────────────────── PROCEDURE pCPOFT CALL: CPOFTNOZ; INPUTS: REAL, REAL, REAL; OUTPUTS: REAL; END // ── Variablen ───────────────────────────────────────── NOZ.PT AS REAL (Description: "Total pressure", Lower: 1000, Value: 200000, Upper: 500000, Spec: Fixed, Unit: "Pa"); NOZ.TT AS REAL (Description: "Total temperature", Lower: 200, Value: 800, Upper: 2000, Spec: Fixed, Unit: "K"); NOZ.FAR AS REAL (Description: "Fuel air ratio", Lower: 0, Value: 0.025, Upper: 0.1, Spec: Fixed, Unit: "none"); NOZ.WGR AS REAL (Description: "Water gas ratio", Lower: 0, Value: 0, Upper: 0.1, Spec: Fixed, Unit: "none"); NOZ.CP AS REAL (Description: "Specific heat", Lower: 700, Value: 1150, Upper: 2000, Spec: Free, Unit: "J/kgK"); NOZ.GAMMAAS REAL (Description: "Isentr. exponent", Lower: 1.0, Value: 1.35, Upper: 2.0, Spec: Free, Unit: "none"); NOZ.PS AS REAL (Description: "Static pressure", Lower: 1000, Value: 100000, Upper: 300000, Spec: Free, Unit: "Pa"); NOZ.RGAS AS REAL (Description: "Gas constant", Lower: 200, Value: 287, Upper: 1000, Spec: Fixed, Unit: "J/kgK"); // ── Gleichungen ─────────────────────────────────────── // Gleichung 1: cp via Built-in Funktion CALL(NOZ.CP) = pCPOFT(NOZ.TT, NOZ.WGR, NOZ.FAR); // Gleichung 2: Isentropenexponent aus cp und Rgas NOZ.GAMMA = NOZ.CP / (NOZ.CP - NOZ.RGAS); // Gleichung 3: Statischer Druck (isentrop, Ma=0.8 angenommen) NOZ.PS = NOZ.PT * (1 - ((NOZ.GAMMA - 1) / 2) * 0.64) ^ (NOZ.GAMMA / (NOZ.GAMMA - 1));
