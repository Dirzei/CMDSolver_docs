Dateistruktur — Überblick

File Structure — Overview

Eine CAS-Datei besteht aus mehreren Sektionen die in beliebiger Reihenfolge auftreten können. Der Parser ist case-insensitiv — Schlüsselwörter können groß oder klein geschrieben werden.

A CAS file consists of multiple sections that may appear in any order. The parser is case-insensitive — keywords can be written in upper or lower case.

// ── Sektion 1: Prozedurendeklaration ──────────────────// ── Section 1: Procedure declaration ────────────────── PROCEDURE prozedurName CALL: BUILT_IN_FUNCTION_NAME; INPUTS: REAL, REAL, ...; OUTPUTS: REAL; END // ── Sektion 2: Variablendeklaration ───────────────────// ── Section 2: Variable declaration ─────────────────── VARIABLE VARIABLENNAME LOWER: 0.0; VALUE: 100.0; UPPER: 500.0; UNIT: "Pa"; END // oder Kurzschreibweise:// or short form: NAME.SUBNAME AS REAL (Description: "Text", Lower: 0, Value: 1, Upper: 10, Spec: Fixed, Unit: "m"); // ── Sektion 3: Startwert-Overrides ────────────────────// ── Section 3: Starting-value overrides ────────────── INITIALIZE VAR = 123.4; VAR.Lower = 0.0; VAR.Upper = 500.0; ENDINIT // ── Sektion 4: Gleichungen ────────────────────────────// ── Section 4: Equations ────────────────────────────── VAR_A = VAR_B * 2.5 + SQRT(VAR_C);
Parsing-Reihenfolge: Der Parser liest die Datei zweimal — erst werden alle Variablen und Prozeduren erfasst, dann werden die Gleichungen interpretiert. Die physische Reihenfolge in der Datei spielt für den Parser keine Rolle.
Parsing order: the parser reads the file twice — first all variables and procedures are collected, then the equations are interpreted. The physical order in the file does not matter to the parser.

Variablennamen — QNAME-Konvention

Variable names — QNAME convention

CMDSolver unterstützt Mehrfach-Punkt-Namen (Qualified Names) für hierarchische Modellstrukturen. Der Punkt ist kein Operator sondern Teil des Namens:

CMDSolver supports multi-dot names (qualified names) for hierarchical model structures. The dot is not an operator but part of the name:

PARTM.F060.PT ← gültiger Variablenname (keine Operatoren)← valid variable name (no operators) GLOBAL.PIVALUE ← hierarchisch: Modul.Variable← hierarchical: module.variable GEOM.RJETPIPE ← hierarchisch: Bereich.Größe← hierarchical: area.quantity AMB.PS ← hierarchisch: Station.Größe← hierarchical: station.quantity

Bugfix B27/B28 (v2.3): bounds overrides in the INITIALIZE block for multi-dot names are correctly extracted via lastIndexOf('.'). PARTM.F060.PS.Upper = ... correctly sets the upper bound of PARTM.F060.PS.

INTEGERPARAMETER — Konstante (neu in v2.10)

INTEGERPARAMETER — Constant (new in v2.10)

INTEGERPARAMETER definiert eine ganzzahlige Konstante die beim Parsing als Präprozessor-Macro überall im Modell substituiert wird — in Arraygrenzen, FOR-Schleifen und Gleichungen.

INTEGERPARAMETER defines an integer constant which, at parse time, is substituted as a preprocessor macro everywhere in the model — in array bounds, FOR loops, and equations.

INTEGERPARAMETER Syntax
INTEGERPARAMETER syntax
// Deklaration// Declaration NSTAGES AS INTEGERPARAMETER (5); // Verwendung in Array-Deklaration// Use in array declaration STAGE_TEMP[NSTAGES] AS REAL (Value: 300, Spec: Free, Unit: "K"); // Verwendung in FOR-Schleife// Use in FOR loop FOR (i = 0:NSTAGES) STAGE_TEMP[i] = T_INLET - i * DELTA_T; END // Verwendung in Gleichungen// Use in equations TOTAL_STAGES = NSTAGES * 1.0; // wird zu: TOTAL_STAGES = 5 * 1.0// becomes: TOTAL_STAGES = 5 * 1.0
Substitution: INTEGERPARAMETER werden als Wortgrenzen-sicheres Macro substituiert — NSTAGES_OLD wird nicht verändert wenn NSTAGES definiert ist.
Substitution: INTEGERPARAMETER values are substituted as word-boundary-safe macros — NSTAGES_OLD is left untouched when NSTAGES is defined.

INITIALIZE Block

INITIALIZE Block

Der INITIALIZE-Block überschreibt Startwerte, Lower- und Upper-Bounds nach dem initialen Parsing. Er wird nach der Variablendeklaration ausgewertet — nützlich um Bounds dynamisch aus anderen Variablen zu berechnen.

The INITIALIZE block overrides starting values and lower/upper bounds after initial parsing. It is evaluated after variable declaration — useful for computing bounds dynamically from other variables.

INITIALIZE Block Syntax
INITIALIZE block syntax
INITIALIZE // Startwert setzen// Set starting value PARTM.F060.PS = AMB.PS * 1.5; // Lower-Bound überschreiben// Override lower bound PARTM.F060.PS.Lower = AMB.PS * 0.5; // Upper-Bound überschreiben// Override upper bound PARTM.F060.PS.Upper = AMB.PS * 4.5; // Konstante// Constant GLOBAL.PIVALUE = 3.14159265358979; ENDINIT
Auswertungsreihenfolge: INITIALIZE-Ausdrücke werden in Dateireihenfolge ausgewertet. Spätere Zeilen können frühere überschreiben. Expressions auf der rechten Seite können andere Variablen referenzieren — deren Werte stammen aus der Variablendeklaration.
Evaluation order: INITIALIZE expressions are evaluated in file order. Later lines can override earlier ones. Expressions on the right side may reference other variables — their values come from the variable declaration.

PROCEDURE — Built-in Funktionen einbinden

PROCEDURE — Embedding Built-in Functions

Prozeduren verbinden CAS-Variablen mit den thermodynamischen Built-in Funktionen aus BIfunctions.java. Die Deklaration definiert Eingang und Ausgang; der Aufruf erfolgt über CALL.

Procedures connect CAS variables to the thermodynamic built-in functions in BIfunctions.java. The declaration defines inputs and outputs; the call is made via CALL.

Prozedur-Deklaration + Aufruf

Gleichungen

Equations

Grundform

Basic form

Jede Gleichung hat die Form LHS = RHS; und wird vom Parser in die Residuumsform LHS − (RHS) umgewandelt. Das Semikolon am Ende ist obligatorisch.

Every equation has the form LHS = RHS; and is converted by the parser into residual form LHS − (RHS). The trailing semicolon is mandatory.

Gleichungs-Beispiele
Equation examples
// Einfache Gleichung// Simple equation PARTM.F060.GAMMAT = PARTM.F060.CPT / (PARTM.F060.CPT - PARTM.F060.RGAS); // Mit mathematischen Funktionen// With mathematical functions PARTM.F060.Q = PARTM.F060.W * SQRT(PARTM.F060.TT) / PARTM.F060.PT; // Potenz// Power PARTM.F060.PS = PARTM.F060.PT * (1 - (PARTM.F060.GAMMAT - 1) / 2) ^ EXP1; // CALL-Gleichung (Built-in Funktion)// CALL equation (built-in function) CALL(PARTM.F060.CP) = pCPOFT(PARTM.F060.TT, PARTM.F060.WGR, PARTM.F060.FAR);

Residuumsform

Residual form

CAS-Gleichung:CAS equation: X = A * B + C;
Residuumsform:Residual form: F(x) = X − (A * B + C)
Solver-Ziel:Solver goal: F(x) = 0 → X = A * B + C ✓

Struktureller IF — VAR.SPEC Bedingung

Structural IF — VAR.SPEC condition

Eine spezielle IF-Form wertet den Status (Fixed/Free) einer Variable zur Parse-Zeit aus — nicht zur Laufzeit. Das erlaubt unterschiedliche Gleichungsstrukturen je nach Modellkonfiguration:

A special IF form evaluates a variable's status (Fixed/Free) at parse time — not at runtime. This allows different equation structures depending on model configuration:

Struktureller IF (VAR.SPEC)
Structural IF (VAR.SPEC)
IF (GLOBAL.STATICSWITCH.SPEC == FIXED) // Diese Gleichung gilt wenn STATICSWITCH fixiert ist// This equation applies when STATICSWITCH is fixed PARTM.F080.PS = PARTM.F060.PS; ELSE // Diese Gleichung gilt wenn STATICSWITCH frei ist// This equation applies when STATICSWITCH is free PARTM.F080.PS = PARTM.F060.PS * GLOBAL.STATICSWITCH; ENDIF

Mathematische Funktionen

Mathematical Functions

Diese Funktionen können direkt in Gleichungen verwendet werden. Sie werden vom Parser in CASprzak-Syntax übersetzt und symbolisch differenziert. Reihenfolge in der FUNC_MAP garantiert korrekte Übersetzung (längere Matches vor kürzeren).

These functions can be used directly in equations. The parser translates them into CASprzak syntax and differentiates them symbolically. The order in FUNC_MAP guarantees correct translation (longer matches before shorter).

Hinweis zu ABS, ROUND, TRUNCATE: Diese Funktionen sind nicht überall differenzierbar — an Knicken und Sprüngen ist die symbolische Ableitung undefiniert. Der Solver kann an solchen Stellen Probleme haben. Falls möglich, glattere Alternativen verwenden.
Note on ABS, ROUND, TRUNCATE: these functions are not differentiable everywhere — at kinks and jumps the symbolic derivative is undefined. The solver can struggle at such points. Use smoother alternatives where possible.
