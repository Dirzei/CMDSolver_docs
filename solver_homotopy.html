Homotopie
Arc-Length Continuation

Der robusteste Solver — verfolgt einen glatten Lösungspfad von einem einfachen Startproblem zum Zielproblem. Konvergiert auch wenn alle anderen Solver scheitern. Langsamer, aber global.

Theoretischer Kontext

Grundidee — allgemein verständlich

Alle anderen Solver starten direkt am Problem F(x) = 0 und können divergieren wenn der Startvektor zu weit von der Lösung entfernt ist. Homotopie geht anders: Man baut eine Brücke vom einfachen zum schwierigen Problem.

Stell dir vor du willst einen Berggipfel erreichen (die Lösung) aber weißt nicht wie. Homotopie beginnt in einem flachen Tal (dem Startproblem) und folgt einem markierten Wanderweg (dem Homotopie-Pfad) schrittweise hinauf. Jeder Schritt ist klein genug um lokal lösbar zu sein.

Homotopie-Funktion:
H(x, t) = t·F(x) + (1−t)·(x − x₀) = 0
t = 0: H(x,0) = x − x₀ = 0 → Lösung: x = x₀ (trivial)
t = 1: H(x,1) = F(x) = 0 → Originalproblem
Arc-Length Parametrisierung:
s = Bogenlänge entlang des Pfades (x(s), t(s))
Vermeidet Singularitäten an Wendepunkten des Pfades

Prädiktor-Korrektor Strategie

CMDSolver implementiert eine Prädiktor-Korrektor-Methode:

Prädiktor: Schätzt den nächsten Punkt auf dem Pfad durch lineare Extrapolation entlang des Tangentenvektors (Euler-Prädiktor).

Korrektor: Verwendet einen inneren Newton-basierten Solver um H(x, t_next) = 0 exakt zu lösen. Standard-Korrektor: NEWTON_ARMIJO. Bei schlecht konditionierten Systemen empfohlen: LEVENBERG_MARQUARDT.

Adaptive Schrittweite

Die Schrittweite ds wird adaptiv angepasst: Bei erfolgreicher Korrektur wird ds vergrößert (schneller vorankommen), bei Stagnation oder Konvergenzschwierigkeiten wird ds halbiert.

fsum = NaN: Der Homotopie-Solver gibt kein fsum über den normalen Kanal aus — er hat eine eigene Konvergenzprüfung über t → 1. NaN bedeutet "nicht verfügbar", nicht "Fehler". Status CONVERGED ist maßgeblich.

Pseudocode

function homotopy_solve(F, x₀, steps, ds_init, innerSolver):
    x ← x₀
    t ← 0.0
    ds ← ds_init
    J₀ ← buildJacobian(F, x₀)     // Anfangspunkt

    while t < 1.0:
        tNext ← min(t + ds, 1.0)

        // ── Prädiktor (Euler entlang Tangente) ──
        tangent ← computeTangent(J₀, x, t)
        x_predict ← x + ds · tangent

        // ── Korrektor (innerer Solver) ──
        H_system ← buildHomotopySystem(F, x₀, tNext)
        result ← innerSolver.solve(H_system, x_predict)

        if result.converged:
            x ← result.solution
            t ← tNext
            ds ← min(ds · 1.5, ds_max)  // vergrößern
        else:
            ds ← ds / 2.0               // halbieren
            if ds < ds_min:
                return STAGNATION, x, t

    return CONVERGED, x, t=1.0
Innerer Solver: Standard ist NEWTON_ARMIJO. Bei schlecht konditionierten Systemen empfohlen: -SH:INNER=LEVENBERG_MARQUARDT

Bekannte Grenzen

Geschwindigkeit: Homotopie ist langsamer als direkte Solver — jeder Schritt auf dem Pfad erfordert einen vollständigen inneren Solver-Lauf. Nur verwenden wenn Newton und LM scheitern.
Pfad-Singularitäten: Wenn der Homotopie-Pfad durch eine Singularität verläuft (Wendepunkt, Bifurkation), kann der Solver stagnieren. Die adaptive Schrittweite erkennt Stagnation und meldet sie.
fsum = NaN: Normal — der Homotopie-Solver gibt kein fsum über den Standard-Kanal aus. CONVERGED-Status ist maßgeblich.
