Grundidee

Core idea

Newton-GSPAR verwendet dasselbe Newton-Raphson-Verfahren wie NEWTON_ARMIJO, ersetzt aber die dichte LU-Zerlegung durch den GSPAR Sparse-LU-Solver. Bei thermodynamischen Systemen ist die Jacobi-Matrix dünn besetzt (sparse) — die meisten Variablen beeinflussen die meisten Gleichungen nicht direkt. GSPAR nutzt diese Struktur aus.

Newton-GSPAR uses the same Newton-Raphson method as NEWTON_ARMIJO but replaces dense LU with the GSPAR sparse-LU solver. For thermodynamic systems the Jacobian is sparsely populated — most variables do not directly affect most equations. GSPAR exploits this structure.

GSPAR — Sparse LU in CMDSolver

GSPAR — sparse LU in CMDSolver

GSPAR (General SPARse) ist eine in CMDSolver integrierte Sparse-LU-Bibliothek. Sie speichert die Jacobi-Matrix im CSR-Format (Compressed Sparse Row) und führt die LU-Zerlegung mit Spaltenpivotierung durch. Die Pivotierungsstrategie MIN_FILL minimiert den "Fill-In" — neue Nicht-Null-Einträge die bei der Faktorisierung entstehen.

GSPAR (General SPARse) is a sparse-LU library integrated into CMDSolver. It stores the Jacobian in CSR (Compressed Sparse Row) format and performs LU factorization with column pivoting. The MIN_FILL pivoting strategy minimizes "fill-in" — new non-zero entries that arise during factorization.

Im Gegensatz zu NEWTON_ARMIJO gibt es kein Backtracking — der volle Newton-Schritt wird immer angewendet. Das macht den Solver schneller pro Iteration, aber weniger robust bei schlechten Startwerten.

In contrast to NEWTON_ARMIJO there is no backtracking — the full Newton step is always applied. That makes the solver faster per iteration but less robust on poor starting values.

Pseudocode

function newton_sparse_solve(F, x₀, tol, maxIter):
    x ← InitGuessApplier(x₀)

    for k = 0 to maxIter:
        J ← buildJacobian(F, x)        // parallel, symbolisch// parallel, symbolic
        f ← F(x)

        // ── GSPAR Sparse-LU ──// ── GSPAR sparse LU ──
        J_sparse ← CSR(J)              // Compressed Sparse Row Format// Compressed Sparse Row format
        [L, U, P] ← gspar_lu(J_sparse) // MIN_FILL Pivotierung// MIN_FILL pivoting
        Δx ← gspar_solve(L, U, P, −f) // Vorwärts-/Rückwärtssubstitution// forward / backward substitution

        // ── Voller Schritt (kein Backtracking) ──// ── Full step (no backtracking) ──
        x ← x + Δx
        x ← PhysicalProjector(x)

        fsum ← Σ|Fᵢ(x)|
        if fsum < tol: return CONVERGED, x, k, fsum

    return NOT_CONVERGED, x, maxIter, fsum

Bekannte Grenzen

Known Limitations

Kein Backtracking: Ohne Armijo-Liniensuche kann der Solver bei schlechten Startwerten divergieren. Für robustere Ausführung → NEWTON_SPARSE_ARMIJO.
No backtracking: without Armijo line search, the solver can diverge on poor starting values. For more robust execution → NEWTON_SPARSE_ARMIJO.
Fill-In: Bei bestimmten Jacobi-Strukturen kann der Fill-In bei der LU-Faktorisierung groß werden. MIN_FILL-Pivotierung minimiert das, kann es aber nicht vollständig vermeiden.
Fill-in: for certain Jacobian structures the fill-in during LU factorization can become large. MIN_FILL pivoting minimizes this but cannot fully prevent it.
