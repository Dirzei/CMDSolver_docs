Theoretischer Kontext

Grundidee

Newton-GSPAR verwendet dasselbe Newton-Raphson-Verfahren wie NEWTON_ARMIJO, ersetzt aber die dichte LU-Zerlegung durch den GSPAR Sparse-LU-Solver. Bei thermodynamischen Systemen ist die Jacobi-Matrix dünn besetzt (sparse) — die meisten Variablen beeinflussen die meisten Gleichungen nicht direkt. GSPAR nutzt diese Struktur aus.

Newton-Schritt: J(xₖ) · Δxₖ = −F(xₖ)
Dichte LU (MatrixSimple): O(n³) Operationen
Sparse LU (GSPAR): O(nnz · log n) ← nnz ≪ n²
Pivotisierungsstrategie: MIN_FILL
// Wählt Pivot-Elemente um Fill-In (neue Nicht-Null-Einträge)
// bei der LU-Faktorisierung zu minimieren → kompakte Faktoren

GSPAR — Sparse LU in CMDSolver

GSPAR (General SPARse) ist eine in CMDSolver integrierte Sparse-LU-Bibliothek. Sie speichert die Jacobi-Matrix im CSR-Format (Compressed Sparse Row) und führt die LU-Zerlegung mit Spaltenpivotierung durch. Die Pivotierungsstrategie MIN_FILL minimiert den "Fill-In" — neue Nicht-Null-Einträge die bei der Faktorisierung entstehen.

Im Gegensatz zu NEWTON_ARMIJO gibt es kein Backtracking — der volle Newton-Schritt wird immer angewendet. Das macht den Solver schneller pro Iteration, aber weniger robust bei schlechten Startwerten.

Pseudocode

function newton_sparse_solve(F, x₀, tol, maxIter):
    x ← InitGuessApplier(x₀)

    for k = 0 to maxIter:
        J ← buildJacobian(F, x)        // parallel, symbolisch
        f ← F(x)

        // ── GSPAR Sparse-LU ──
        J_sparse ← CSR(J)              // Compressed Sparse Row Format
        [L, U, P] ← gspar_lu(J_sparse) // MIN_FILL Pivotierung
        Δx ← gspar_solve(L, U, P, −f) // Vorwärts-/Rückwärtssubstitution

        // ── Voller Schritt (kein Backtracking) ──
        x ← x + Δx
        x ← PhysicalProjector(x)

        fsum ← Σ|Fᵢ(x)|
        if fsum < tol: return CONVERGED, x, k, fsum

    return NOT_CONVERGED, x, maxIter, fsum

Bekannte Grenzen

Kein Backtracking: Ohne Armijo-Liniensuche kann der Solver bei schlechten Startwerten divergieren. Für robustere Ausführung → NEWTON_SPARSE_ARMIJO.
Fill-In: Bei bestimmten Jacobi-Strukturen kann der Fill-In bei der LU-Faktorisierung groß werden. MIN_FILL-Pivotierung minimiert das, kann es aber nicht vollständig vermeiden.
