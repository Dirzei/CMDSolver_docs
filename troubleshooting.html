Konvergenzprobleme

Convergence Problems

❌ Solver meldet NOT_CONVERGED — keine FehlermeldungSolver reports NOT_CONVERGED — no error message
→ 1
Schlechter Startvektor?Bad starting vector? Diagnose-Modus aktivieren: -DI lässt InitialValueAnalyzer die Startwerte optimieren. Oft reicht das.Enable diagnostic mode: -DI lets InitialValueAnalyzer optimize the starting values. Often that's enough. 
java cmd.CASSolver -I:model.cas -DI
→ 2
Startvektor inspizieren:Inspect the starting vector: -DV:start.txt schreibt den tatsächlichen Startvektor vor Iteration 0. Physikalisch plausibel? Temperatur > 0K? Druck > 0Pa?-DV:start.txt writes the actual starting vector before iteration 0. Physically plausible? Temperature > 0K? Pressure > 0Pa? 
java cmd.CASSolver -I:model.cas -S:NEWTON_ARMIJO -DV:start.txt
→ 3
Andere Solver versuchen:Try other solvers: -TEST zeigt alle 7 Solver. Konvergiert einer davon → Startwert-Problem. Konvergiert keiner → Modell-Problem.-TEST runs all 7 solvers. If one converges → starting-value issue. If none converges → model issue.
→ 4
Levenberg-Marquardt als robustere Alternative:Levenberg-Marquardt as a more robust alternative: Bei κ-Warnungen im Log immer LM versuchen.Always try LM when κ warnings appear in the log. 
java cmd.CASSolver -I:model.cas -S:LEVENBERG_MARQUARDT -DI
→ 5
Homotopie als letztes Mittel:Homotopy as a last resort: 
java cmd.CASSolver -I:model.cas -S:HOMOTOPY -SH:CRITICAL -SH:INNER=LEVENBERG_MARQUARDT
🔄 Solver iteriert bis maxIter ohne Verbesserung (fsum stagniert)Solver iterates to maxIter without improvement (fsum stagnates)
→ 1
fsum-Verlauf im Log prüfen:Inspect fsum trajectory in the log: Sinkt fsum gar nicht? → Schlechter Startvektor oder falsches Vorzeichen in Gleichung. Sinkt fsum anfangs, stagniert dann? → Möglicherweise zwei Lösungen oder nahezu singuläre Jacobi.Does fsum not drop at all? → Bad starting vector or wrong sign in an equation. Drops initially, then stagnates? → Possibly two solutions or nearly singular Jacobian.
→ 2
Residuen-Normierung aktivieren:Enable residual normalization: Bei gemischten Einheiten (Pa + kg/s) kann eine Gleichung dominieren. -SN normiert auf Startwert-Residuen.With mixed units (Pa + kg/s) one equation can dominate. -SN normalizes to starting-value residuals. 
java cmd.CASSolver -I:model.cas -SN
→ 3
Gleichgewicht prüfen:Check balance: n freie Variablen = n Gleichungen? Log zeigt beim Start: Starting ... [n=X, maxIter=100, ...] — X muss der Anzahl freier Variablen entsprechen.n free variables = n equations? At startup the log shows: Starting ... [n=X, maxIter=100, ...] — X must match the number of free variables.

Parser-Fehler

Parser Errors

⚠️ ParseError: "Variable not found" oder stille FehlerParseError: "Variable not found" or silent failures
→ 1
ParseErrors im SolverResult prüfen:Inspect ParseErrors on SolverResult: 
SolverResult r = api.solve();
r.getParseErrors().forEach(e -> System.err.println(e.format()));
Jeder ParseError enthält Zeilennummer und Kontext.Every ParseError contains a line number and context.
→ 2
Variablenname-Tippfehler:Variable-name typo: CMDSolver ist case-insensitiv — aber Punkt-Notation muss exakt stimmen. PARTM.F060.PS ≠ PARTM.F060.Ps (Letzteres würde nach toUpperCase zu ersterem).CMDSolver is case-insensitive — but the dot notation must match exactly. PARTM.F060.PS ≠ PARTM.F060.Ps (the latter would become the former after toUpperCase).
→ 3
Variable deklariert aber nicht in Gleichung:Variable declared but not used in equations: Freie Variable ohne Gleichung → System ist unterbestimmt. Jede freie Variable braucht genau eine Gleichung die sie "bestimmt".Free variable without an equation → the system is underdetermined. Every free variable needs exactly one equation that "determines" it.
⚠️ INITIALIZE-Block Override wird ignoriertINITIALIZE block override is ignored
→ 1
Syntax für Mehrfach-Punktnamen:Syntax for multi-dot names: Für PARTM.F060.PS.Upper = ... muss der vollständige Name vor dem letzten Punkt stehen. Der Parser verwendet lastIndexOf('.').For PARTM.F060.PS.Upper = ... the full name must appear before the last dot. The parser uses lastIndexOf('.'). 
INITIALIZE
  PARTM.F060.PS = 100000;          // Startwert
  PARTM.F060.PS.Upper = 200000;   // Upper-Bound
  PARTM.F060.PS.Lower = 50000;    // Lower-Bound
ENDINIT
→ 2
initStructSwitches vor INITIALIZE:initStructSwitches before INITIALIZE: Strukturelle IF-Bedingungen (VAR.SPEC==FIXED) müssen vor dem INITIALIZE-Block ausgewertet werden. Das macht EqnSystem automatisch — wenn der Aufruf fehlt (z.B. bei direktem EqnData-Aufruf) funktioniert INITIALIZE nicht.Structural IF conditions (VAR.SPEC==FIXED) must be evaluated before the INITIALIZE block. EqnSystem does this automatically — if the call is missing (e.g., on direct EqnData usage) INITIALIZE will not work.
🔴 Kompilierfehler: hunderte Fehler nach Datei-UpdateCompilation errors: hundreds of errors after file update
→ 1
Versionsmischung:Version mixing: Wahrscheinlichste Ursache. Dateien aus v2.3 und v2.4+ dürfen nicht gemischt werden. v2.4's EqnSysReader ruft ParseError-Methoden auf die in v2.3's SystemData fehlen.Most likely cause. Files from v2.3 and v2.4+ must not be mixed. v2.4's EqnSysReader calls ParseError methods that are missing from v2.3's SystemData. Lösung:Fix: Alle Dateien aus demselben ZIP kopieren.Copy all files from the same ZIP.
→ 2
Doppelte Klassendeklaration:Duplicate class declaration: 
grep -c "^public class EqnData" EqnData.java  // muss 1 ergeben
Wenn 2: Javadoc steht nach statt vor public class.If 2: Javadoc is placed after instead of before public class.

Konditionszahl-Warnungen

Condition Number Warnings

⚠️ Log: "kappa=4.62e+11 [POOR] — ill-conditioned Jacobian"Log: "kappa=4.62e+11 [POOR] — ill-conditioned Jacobian"

Konditionszahl κ misst wie empfindlich das System auf kleine Änderungen reagiert. κ > 10⁸ ist problematisch, κ > 10¹² gefährlich für Newton.

The condition number κ measures how sensitive the system is to small changes. κ > 10⁸ is problematic, κ > 10¹² dangerous for Newton.

→ 1
Ursachen für hohes κ:Causes of high κ: Gemischte Einheiten (Pa ~ 10⁵, kg/s ~ 1, dimensionslos ~ 10⁻³) erzeugen riesige Spanne in der Jacobi. Verschiedene Größenordnungen werden direkt im Jacobi-Eintrag sichtbar.Mixed units (Pa ~ 10⁵, kg/s ~ 1, dimensionless ~ 10⁻³) produce a huge span in the Jacobian. Different orders of magnitude become visible directly in the Jacobian entries.
→ 2
Sofortmaßnahme: Levenberg-Marquardt:Quick fix: Levenberg-Marquardt: LM ist robust bis κ ~ 10²⁵. Einfach Solver wechseln:LM is robust up to κ ~ 10²⁵. Simply switch solvers: 
java cmd.CASSolver -I:model.cas -S:LEVENBERG_MARQUARDT
→ 3
Mittelfristig: Gleichungen normieren:Medium-term: normalize equations: Gleichungen in Pa durch 1e5 teilen, kg/s-Gleichungen durch 1 lassen. Das reduziert die Spanne in der Jacobi und verbessert κ um 2–4 Größenordnungen.Divide Pa equations by 1e5, leave kg/s equations as-is. This reduces the span in the Jacobian and improves κ by 2–4 orders of magnitude.

NaN und Divergenz

NaN and Divergence

💥 Log: "NaN detected — treating as divergence"Log: "NaN detected — treating as divergence"
→ 1
Physikalisch unmöglicher Zwischenwert:Physically impossible intermediate value: Eine Gleichung hat einen Wert außerhalb des physikalischen Bereichs erzeugt — z.B. negative Temperatur in SQRT(T), Division durch Null. PhysicalProjector fängt viele Fälle, aber nicht alle.An equation produced a value outside the physical range — e.g., negative temperature in SQRT(T), division by zero. PhysicalProjector catches many cases, but not all.
→ 2
Bounds strenger setzen:Set tighter bounds: Lower-Bounds für T (≥ 1K), p (≥ 1Pa), Flächen (≥ 1e-6 m²) verhindern physikalisch unmögliche Zwischenwerte. PhysicalProjector projiziert nur auf User-Bounds wenn diese enger sind als die physikalischen Defaults.Lower bounds for T (≥ 1K), p (≥ 1Pa), areas (≥ 1e-6 m²) prevent physically impossible intermediate values. PhysicalProjector only projects onto user bounds when they are tighter than the physical defaults.
→ 3
Armijo-Liniensuche hilft:Armijo line search helps: NEWTON_SPARSE_ARMIJO halbiert den Schritt wenn der Versuchspunkt NaN erzeugt. Ohne Armijo (NEWTON_SPARSE) kann NaN sofort auftreten.NEWTON_SPARSE_ARMIJO halves the step when the trial point produces NaN. Without Armijo (NEWTON_SPARSE), NaN can occur immediately.
📊 Homotopie meldet fsum = NaNHomotopy reports fsum = NaN

Das ist normal. Der Homotopie-Solver gibt kein fsum über den Standard-Kanal aus — er hat eine eigene interne Konvergenzprüfung über den Pfadfortschritt t → 1. Nur der isConverged()-Status ist maßgeblich.

This is normal. The homotopy solver does not emit fsum on the standard channel — it has its own internal convergence check based on path progress t → 1. Only the isConverged() status matters.

Performance-Probleme

Performance Problems

🐢 Solver ist sehr langsam bei großem System (n > 200)Solver is very slow on large systems (n > 200)
→ 1
Sparse-LU verwenden:Use sparse LU: NEWTON_ARMIJO verwendet dichte LU (O(n³)). NEWTON_SPARSE_ARMIJO verwendet GSPAR Sparse-LU (O(nnz)) — bis 10× schneller.NEWTON_ARMIJO uses dense LU (O(n³)). NEWTON_SPARSE_ARMIJO uses GSPAR sparse LU (O(nnz)) — up to 10× faster.
→ 2
Broyden-Sparse für Parameterstudien:Broyden-Sparse for parameter studies: Wenn viele ähnliche Betriebspunkte gelöst werden: BROYDEN_SPARSE spart Jacobi-Neuaufbauten. ~9ms vs ~30ms für SimpleSystem.When many similar operating points are solved: BROYDEN_SPARSE saves Jacobian rebuilds. ~9ms vs ~30ms for SimpleSystem.
→ 3
BatchRunner für Parameterstudien:BatchRunner for parameter studies: CSV-Datei mit allen Betriebspunkten → -I:studie.csv. Läuft alle Punkte sequenziell mit Warm-Start-Option.CSV file with all operating points → -I:studie.csv. Runs all points sequentially with the warm-start option.

Häufige Fragen (FAQ)

Frequently Asked Questions (FAQ)

Wie viele Gleichungen kann CMDSolver lösen?
How many equations can CMDSolver handle?
Theoretisch unbegrenzt. Praktisch getestet bis ~600 Gleichungen (623-Gleichungen Benchmark). Mit GSPAR Sparse-LU sind 1000–2000 Gleichungen realistisch. Bei n > 2000 wird GMRES als linearer Solver benötigt (Roadmap R-02).Theoretically unlimited. Practically tested up to ~600 equations (623-equation benchmark). With GSPAR sparse LU, 1000–2000 equations are realistic. For n > 2000, GMRES is needed as a linear solver (Roadmap R-02).
Warum ist die Jacobi dicht obwohl das System sparse aussieht?
Why is the Jacobian dense even though the system looks sparse?
In thermodynamischen Modellen hängen viele Variablen über physikalische Zusammenhänge zusammen — Gaszusammensetzung beeinflusst cp beeinflusst κ beeinflusst Schallgeschwindigkeit beeinflusst Machzahl usw. Das erzeugt trotzdem eine relativ dünn besetzte Jacobi (5–15% Besetzung) — GSPAR Sparse-LU ist dennoch deutlich schneller als dichte LU.In thermodynamic models, many variables are coupled via physical relationships — gas composition affects cp affects κ affects speed of sound affects Mach number, etc. This still produces a relatively sparse Jacobian (5–15% fill) — GSPAR sparse LU is nevertheless much faster than dense LU.
Kann ich CMDSolver in einem Multi-Thread-Kontext verwenden?
Can I use CMDSolver in a multi-threaded context?
Ja — eine SolverAPI-Instanz pro Thread. Instanzen sind nicht thread-sicher untereinander, aber mehrere unabhängige Instanzen können parallel laufen. Der interne Jacobi-Aufbau ist aktuell nicht parallelisiert (PARALLEL_JACOBI_THRESHOLD = 99999).Yes — one SolverAPI instance per thread. Instances are not thread-safe with each other, but multiple independent instances can run in parallel. Internal Jacobian assembly is currently not parallelized (PARALLEL_JACOBI_THRESHOLD = 99999).
Warum hat die CAS-Datei Semikolon am Ende jeder Gleichung?
Why does the CAS file have a semicolon at the end of every equation?
Das Semikolon ist das Gleichungsende-Zeichen — der Parser behandelt es als Abschluss der Residuumsform LHS − (RHS) = 0. Ohne Semikolon kann der Parser nicht unterscheiden ob die Zeile weitergeht. In der AS-REAL-Kurzform ist das Semikolon ebenfalls obligatorisch.The semicolon is the equation terminator — the parser treats it as the end of the residual form LHS − (RHS) = 0. Without it, the parser cannot tell whether the line continues. In the AS-REAL short form the semicolon is mandatory too.
Was bedeutet "Fixed" vs "Free" für eine Variable?
What does "Fixed" vs "Free" mean for a variable?
Fixed: Die Variable ist eine bekannte Randbedingung — ihr Wert ist vorgegeben und wird vom Solver nicht verändert. Free: Die Variable ist eine Unbekannte die der Solver bestimmt. Anzahl Free-Variablen muss gleich Anzahl der Gleichungen sein.Fixed: the variable is a known boundary condition — its value is given and not changed by the solver. Free: the variable is an unknown that the solver determines. The number of free variables must equal the number of equations.
Kann ich die Lösung eines Betriebspunkts als Startvektor für den nächsten verwenden?
Can I use the solution of one operating point as the starting vector for the next?
Mit der -DV: Option wird der aktuelle Startvektor in eine Datei geschrieben die dann mit -U: als Startvektor für den nächsten Lauf verwendet werden kann. SolverState Warm-Start (Roadmap R-14) wird das automatisieren.With the -DV: option the current starting vector is written to a file which can then be passed via -U: as the starting vector for the next run. SolverState warm-start (Roadmap R-14) will automate this.
Warum funktionieren ABS(), ROUND() und TRUNCATE() manchmal schlecht mit Newton?
Why do ABS(), ROUND(), and TRUNCATE() sometimes work badly with Newton?
Diese Funktionen sind an Knicken und Sprüngen nicht differenzierbar. Newton braucht glatte Ableitungen. An den Unstetigkeitsstellen (ABS bei 0, ROUND bei .5) ist die symbolische Ableitung undefiniert und die numerische Ableitung ungenau. Als Alternative: glatte Approximationen verwenden, z.B. ABS(x) ≈ SQRT(x^2 + ε) mit kleinem ε > 0.These functions are not differentiable at kinks and jumps. Newton needs smooth derivatives. At the discontinuities (ABS at 0, ROUND at .5) the symbolic derivative is undefined and the numerical one is inaccurate. As an alternative, use smooth approximations, e.g., ABS(x) ≈ SQRT(x^2 + ε) with small ε > 0.
Wie debugge ich eine Gleichung die immer NaN liefert?
How do I debug an equation that always returns NaN?
Startvektor mit -DV:start.txt speichern, Werte manuell in einer Tabellenkalkulation nachrechnen. Welche Variable hat einen unmöglichen Wert? Dann Bounds für diese Variable strenger setzen und -DI aktivieren.Save the starting vector with -DV:start.txt, then recompute values manually in a spreadsheet. Which variable has an impossible value? Tighten that variable's bounds and enable -DI.
