Pragmatischer Continuation-Wrapper über Newton-Armijo (oder andere innere Solver). Versucht zuerst direkten Lösungsweg, fällt bei Bedarf auf λ-Continuation zurück. Phase 1 (try-direct) funktioniert produktiv, Phase 2 (Continuation) ist auf NozzleSystem nicht zuverlässig — siehe StatusStatus.

Pragmatic continuation wrapper around Newton-Armijo (or other inner solvers). First attempts a direct solve, falls back to λ-continuation when needed. Phase 1 (try-direct) works in production, Phase 2 (continuation) is not reliable on NozzleSystem — see Status.

Status — wichtig zu lesen

Status — important to read

Phase 1 (try-direct-first) ist produktiv nutzbar. Der Wrapper versucht zuerst den direkten inneren Solver mit geerbter Skalierungsstrategie. Auf NozzleSystem konvergiert das in 5 Iter (mit EQUILIBRATE) bzw. 6 Iter (ohne) in ~0.4 Sekunden — identisch zu direktem NEWTON_ARMIJO. Praktisch sinnvoll als "sicherer Wrapper" der bei Bedarf eine Continuation-Schicht hinzufügt.
Phase 1 (try-direct-first) is production-ready. The wrapper first tries the direct inner solver with the inherited scaling strategy. On NozzleSystem this converges in 5 iter (with EQUILIBRATE) or 6 iter (without) in ~0.4 seconds — identical to direct NEWTON_ARMIJO. Practically useful as a "safe wrapper" that adds a continuation layer when needed.
Phase 2 (λ-Continuation) ist EXPERIMENTAL — derzeit nicht produktiv konvergent auf NozzleSystem. Wenn Phase 1 scheitert (oder per -SH:DIRECT=OFF übersprungen wird), startet die λ-Schleife. Auf NozzleSystem divergiert der innere Solver auf dem H_λ-System (siehe Diagnose): Skalen-Mismatch zwischen linearem Anteil (1-λ)·J₀·(x-x₀) und nichtlinearem Anteil λ·F(x) bei großen (x-x₀)-Abweichungen.
Phase 2 (λ continuation) is EXPERIMENTAL — currently does not converge productively on NozzleSystem. When phase 1 fails (or is skipped via -SH:DIRECT=OFF), the λ loop starts. On NozzleSystem the inner solver diverges on the H_λ system (see diagnostic): a scale mismatch between the linear part (1-λ)·J₀·(x-x₀) and the nonlinear part λ·F(x) at large (x-x₀) deviations.
Empfehlung:
  • Für NozzleSystem-artige Probleme: stattdessen direkt NEWTON_ARMIJO mit -SC:EQUILIBRATE oder LEVENBERG_MARQUARDT verwenden
  • ADAPTIVE_LAMBDA sinnvoll als Wrapper wenn Du nicht weißt ob das Modell direkt konvergiert — Phase 1 versucht's, Phase 2 ist Fallback (mit den genannten Limitierungen)
Recommendation:
  • For NozzleSystem-like problems: use NEWTON_ARMIJO with -SC:EQUILIBRATE or LEVENBERG_MARQUARDT directly instead
  • ADAPTIVE_LAMBDA is useful as a wrapper when you don't know whether the model converges directly — phase 1 tries, phase 2 is fallback (with the limitations noted)

Grundidee — Wrapper über bewährte Solver

Idea — wrapper over proven solvers

Statt eigene Continuation-Mathematik (wie HOMOTOPY oder ARC_LENGTH) nutzt ADAPTIVE_LAMBDA den existierenden Newton-Armijo-Solver als Engine und legt eine zweistufige Schicht darüber:

Instead of its own continuation mathematics (like HOMOTOPY or ARC_LENGTH), ADAPTIVE_LAMBDA uses the existing Newton-Armijo solver as the engine and adds a two-stage layer on top:

Was diese Architektur attraktiv macht

Why this architecture is attractive

  • Nutzt was funktioniert: Newton-Armijo+EQUILIBRATE konvergiert NozzleSystem in 5 Iter — wir bauen darüber, statt parallel.
  • Kein eigener Predictor: x_current ist Predictor — Newton's Armijo macht den Rest (Schrittdämpfung, Akzeptanz).
  • Inkrementell sicher: Phase 1 ist ein einfacher Wrapper-Aufruf. Phase 2 wird nur aktiv wenn nötig.
  • Innerer Solver erbt Skalierung: -SC:EQUILIBRATE wirkt automatisch auf den inneren Workhorse (Variante c).
  • Uses what works: Newton-Armijo+EQUILIBRATE converges NozzleSystem in 5 iter — we build on top, not in parallel.
  • No custom predictor: x_current is the predictor — Newton's Armijo does the rest (step damping, acceptance).
  • Incrementally safe: phase 1 is a simple wrapper call. Phase 2 only activates when needed.
  • Inner solver inherits scaling: -SC:EQUILIBRATE automatically affects the inner workhorse (variant c).

Innerer Solver — Auswahl

Inner solver — selection

Der innere Solver wird so konfiguriert:

The inner solver is configured as follows:

  • Algorithmus: NEWTON_ARMIJO als sicherer Default. Per -SH:INNER=LEVENBERG_MARQUARDT (oder andere SolverTypes) überschreibbar.
  • Skalierungsstrategie: Geerbt aus dem Hauptaufruf (-SC:) — das gilt für beide Phasen.
  • maxIter, tolerance: Aus der äußeren SolverConfig übernommen.
  • Algorithm: NEWTON_ARMIJO as safe default. Overridable via -SH:INNER=LEVENBERG_MARQUARDT (or other SolverTypes).
  • Scaling strategy: inherited from the main call (-SC:) — applies to both phases.
  • maxIter, tolerance: taken from the outer SolverConfig.

Pseudocode

Pseudocode

solve(sysData, useInitData):
  x₀ = extractFreeValues(sysData)

  // ---- Phase 1: try-direct-first ----
  if hcfg.tryDirectFirst:
    innerCfg = buildInnerConfig()              // Newton-Armijo + EQUILIBRATE etc.
    direct = innerCfg.solver.solve(sysData)
    if direct.converged:
      return success(direct)
    reset values to x₀                          // wichtig: x kann driften

  // ---- Phase 2: λ-Continuation ----
  J₀ = FD-Jacobi am Startpunkt
  x_current = x₀
  λ = 0,  dλ = 0.5
  innerSolver = SolverFactory.create(innerCfg)

  while λ < 1:
    λ_next = min(λ + dλ, 1)
    subSystem = buildHomotopySystem(sysData, J₀, x₀, λ_next)
    applyValuesToSystem(subSystem, x_current)
    inner = innerSolver.solve(subSystem)

    if inner.converged:
      x_current = extractFreeValues(subSystem)
      λ = λ_next
      if inner.iter < target/2:
        dλ = min(dλ * 1.5, 0.5)
    else:
      dλ /= 2
      if dλ < 1e-3: abort

  return success(x_current)

Diagnose der Phase-2-Divergenz

Diagnostic of phase-2 divergence

Das Sub-System F_λ(x) = (1-λ)·J₀·(x-x₀) + λ·F(x) = 0 hat bei NozzleSystem ein konzeptionelles Skalen-Problem:

The sub-system F_λ(x) = (1-λ)·J₀·(x-x₀) + λ·F(x) = 0 has a conceptual scale problem on NozzleSystem:

  • Linearer Anteil J₀·(x-x₀) wächst linear mit |x-x₀|. Bei großen Newton-Schritten dominiert er F(x).
  • Bounds-Verletzungen: FULLM.F080.PS = -2.02e+06 (Lower=1000), FULLM.F180.RHO = -22 (Lower=0) — Newton's Schritt treibt Variablen weit aus zulässigen Bereichen.
  • Equilibrator-Skalen springen zwischen Iter sprunghaft (rowScale_min: 2.16e-12 → 2.96e-16) — System verliert seine Konsistenz.
  • The linear part J₀·(x-x₀) grows linearly with |x-x₀|. On large Newton steps it dominates F(x).
  • Bounds violations: FULLM.F080.PS = -2.02e+06 (Lower=1000), FULLM.F180.RHO = -22 (Lower=0) — Newton's step pushes variables far outside admissible ranges.
  • Equilibrator scales jump abruptly between iterations (rowScale_min: 2.16e-12 → 2.96e-16) — the system loses its consistency.

Das ist kein Solver-Bug, sondern eine Folge der Problem-Topologie: das Modell hat enge Bounds (Drücke ≥ 1000 Pa) und Newton-Armijo's Armijo-Dämpfung reicht nicht aus um auf dem H_λ-System zu konvergieren — selbst wenn er auf dem reinen F-System konvergieren würde.

This is not a solver bug but a consequence of the problem topology: the model has tight bounds (pressures ≥ 1000 Pa) and Newton-Armijo's Armijo damping is not sufficient to converge on the H_λ system — even when it would converge on the plain F system.

Grenzen — wann nicht verwenden

Limits — when not to use

  • Phase 2 auf Modellen mit engen Bounds und kappa > 10⁹: Funktioniert nicht zuverlässig (siehe NozzleSystem-Diagnose oben). Diese Modelle sind besser direkt mit Newton-Armijo+EQUILIBRATE oder LM zu lösen.
  • Phase 1 wenn Newton sicher direkt scheitert: Spart ein paar Iterationen wenn man Continuation eh braucht — dann -SH:DIRECT=OFF setzen. Aber ehrlicherweise ist dann auch Phase 2 fragwürdig.
  • Phase 2 on models with tight bounds and kappa > 10⁹: Does not work reliably (see NozzleSystem diagnostic above). These models are better solved directly with Newton-Armijo+EQUILIBRATE or LM.
  • Phase 1 when Newton is sure to fail directly: saves a few iterations if continuation is needed anyway — then set -SH:DIRECT=OFF. But honestly, phase 2 is also questionable in that case.

Wann er sinnvoll ist

When it is useful

  • Als Wrapper bei unbekanntem Modell-Verhalten: Phase 1 versucht's pragmatisch, Phase 2 ist Sicherheitsnetz. Bei moderaten Modellen kann Phase 2 helfen.
  • Phase 1 alleine als Default-Solver: Identische Performance zu Newton-Armijo, aber mit eingebautem Fallback-Verhalten falls die innere Konvergenz scheitert.
  • As a wrapper for unknown model behavior: phase 1 tries pragmatically, phase 2 is the safety net. On moderate models phase 2 can help.
  • Phase 1 alone as default solver: identical performance to Newton-Armijo, but with built-in fallback behavior if inner convergence fails.

Roadmap

Roadmap

Phase 2 könnte mit folgenden Verbesserungen produktiv werden:

Phase 2 could become production-ready with the following improvements:

  • Skalen-bewusste H_λ-Definition: F_λ = (1-λ)·D·(x-x₀) + λ·F(x) mit Diagonalmatrix D passend zu F-Skalen
  • Bounds-Vorhersage im äußeren Loop — kleineres dλ wählen wenn Bounds-Verletzung droht
  • Trust-Region zwischen λ-Schritten
  • Scale-aware H_λ definition: F_λ = (1-λ)·D·(x-x₀) + λ·F(x) with diagonal matrix D matched to F scales
  • Bounds prediction in the outer loop — pick a smaller dλ when bounds violation looms
  • Trust region between λ steps

Diese Verbesserungen sind nicht implementiert weil das vorhandene Test-Modell (NozzleSystem mit GAMMA-Fix) Phase 1 löst und kein weiteres pathologisches Modell zur Validierung verfügbar ist.

These improvements are not implemented because the existing test model (NozzleSystem with GAMMA fix) is solved by phase 1 and no further pathological model is available for validation.
