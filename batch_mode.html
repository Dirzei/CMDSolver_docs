Automatisiertes Lösen von N Betriebspunkten aus einer CSV-Datei — mit Warm-Start, Konvergenzprotokoll und strukturierter Ausgabe.

Automated solving of N operating points from a CSV file — with warm-start, convergence log, and structured output.

Überblick

Overview

Der Batch-Modus löst dasselbe Gleichungssystem (CAS-Datei) für viele verschiedene Betriebspunkte. Jeder Betriebspunkt definiert neue Werte für ausgewählte fixierte Eingabevariablen — alle freien Variablen werden vom Solver berechnet.

Batch mode solves the same equation system (CAS file) for many different operating points. Each operating point defines new values for selected fixed input variables — all free variables are computed by the solver.

BatchRunner wird automatisch aktiviert wenn die -I:-Datei die Endung .csv hat. Die zugehörige CAS-Datei muss im selben Verzeichnis liegen und denselben Dateinamen haben:

BatchRunner is activated automatically when the -I: file has the .csv extension. The matching CAS file must be in the same directory and share the same filename:

parameterstudie.csv    ← Eingabe: -I:parameterstudie.csv
parameterstudie.cas    ← Gleichungssystem (automatisch gesucht, gleicher Name)parameterstudie.csv    ← Input: -I:parameterstudie.csv
parameterstudie.cas    ← Equation system (auto-located, same name)
Abgrenzung der Flags: -I: bestimmt immer die Haupteingabedatei — .cas für Single-Run, .csv für Batch-Modus.
-U: ist für Variablen-Overrides (Einzelpunkte, Key:Value Format).
-C: gibt die CAS-Basisdatei explizit an wenn sie nicht denselben Namen wie die CSV hat.
Flag boundaries: -I: always denotes the main input file — .cas for single run, .csv for batch mode.
-U: is for variable overrides (single point, Key:Value format).
-C: explicitly specifies the CAS base file when it does not share the CSV's name.

Variablennamen prüfen: Wenn ein Variablenname im Header nicht in der CAS-Datei gefunden wird, bricht BatchRunner mit einem Fehler ab. Exakte Schreibweise aus der CAS-Datei verwenden (Punkte, Leerzeichen, Indizes).
Check variable names: if a variable name in the header is not found in the CAS file, BatchRunner aborts with an error. Use the exact spelling from the CAS file (dots, spaces, indices).
Nur Fixed-Variablen als Input: Die CSV-Eingabe überschreibt die Value-Felder der angegebenen Variablen für jeden Run. Variablen die in der CAS-Datei als Spec: Free deklariert sind können nicht als CSV-Input verwendet werden — BatchRunner meldet dies als Fehler.
Only fixed variables as input: CSV input overwrites the Value field of the listed variables for every run. Variables declared as Spec: Free in the CAS file cannot be used as CSV input — BatchRunner reports this as an error.

Warm-Start

Warm-Start

BatchRunner verwendet automatisch den Lösungsvektor des vorherigen erfolgreichen Runs als Startvektor für den nächsten Run. Das ist der größte Performancevorteil des Batch-Modus:

BatchRunner automatically uses the solution vector of the previous successful run as the starting vector for the next run. This is the biggest performance benefit of batch mode:

SituationSituationStartvektor für Run NStarting vector for run N
Run 1 (erster Run)Run 1 (first run) Startwerte aus der CAS-Datei (Value-Felder)Starting values from the CAS file (Value fields)
Run N, vorheriger Run konvergiertRun N, previous run converged Lösung von Run N-1 — Warm-StartSolution of run N-1 — warm-start
Run N, vorheriger Run nicht konvergiertRun N, previous run did not converge Letzter konvergierter Zustand oder CAS-StartwerteLast converged state or CAS starting values
Vorteil: Bei nahe beieinanderliegenden Betriebspunkten (z.B. Kennfeldberechnung in kleinen Schritten) konvergiert der Solver typisch in 2-4 Iterationen statt 10-15. Das reduziert die Gesamtlaufzeit einer Parameterstudie um Faktor 3-5.
Advantage: for closely spaced operating points (e.g., map computation in small steps), the solver typically converges in 2–4 iterations instead of 10–15. This reduces the total runtime of a parameter study by a factor of 3–5.
Hinweis: Wenn die Betriebspunkte in der CSV-Datei weit auseinander liegen, kann der Warm-Start den Solver fehlleiten. In diesem Fall ist es besser die Betriebspunkte nach Ähnlichkeit zu sortieren oder ohne Warm-Start zu arbeiten.
Note: when the operating points in the CSV are far apart, the warm-start can mislead the solver. In that case it is better to sort the operating points by similarity or to work without warm-start.

Warm-Start Sprung-ErkennungWarm-Start Jump Detection

Bei Parameterstudien mit Sägezahnkurven als Input (z.B. Druck steigt, fällt, steigt wieder) kann der Warm-Start schaden: der Solver startet mit der Lösung des letzten Betriebspunkts, der weit entfernt ist.

Die Sprung-Erkennung verwirft den Warm-Start automatisch wenn sich eine Input-Variable um mehr als den Schwellwert ändert:

For parameter studies with sawtooth-shaped inputs (e.g. pressure rises, falls, rises again), the warm-start can be counterproductive: the solver starts from the previous solution which may be far away.

Jump detection automatically discards the warm-start when any input variable changes by more than the threshold:

relJump = |new - old| / max(|old|, |new|, 1e-10)
Flag BeschreibungDescription StandardDefault
-BC:JUMPTHRESH=0.20 Warm-Start verwerfen wenn relativer Sprung > 20% Discard warm-start if relative jump > 20% Ja (20%) Yes (20%)
-BC:JUMPTHRESH=0.10 Engere Schwelle für feine Sägezahnkurven Tighter threshold for fine sawtooth curves —
-BC:JUMPTHRESH=0 Sprung-Erkennung deaktivieren Disable jump detection entirely —

Log-Ausgabe bei erkanntem Sprung:

Log output when jump detected:

Run 4: input jump 45% > threshold 20% — warm-start discarded
Run 4: CONVERGED  iter=11  fsum=2.3e-09  t=0.387s
Empfehlung: Betriebspunkte in der CSV monoton sortieren (aufsteigend oder absteigend) wenn möglich — dann ist der Warm-Start immer günstig und die Sprung-Erkennung greift selten ein.
Recommendation: Sort operating points monotonically (ascending or descending) in the CSV when possible — the warm-start is always beneficial and jump detection rarely triggers.

Hinweise & Tipps

Notes & Tips

CSV-Datei erstellen

Creating the CSV file

Die CSV-Datei kann in Excel, LibreOffice Calc oder einem Texteditor erstellt werden. Wichtig: als UTF-8 oder ASCII speichern, nicht als Excel-Format (.xlsx).

The CSV file can be created in Excel, LibreOffice Calc, or a text editor. Important: save as UTF-8 or ASCII, not as Excel format (.xlsx).

Betriebspunkte sortieren

Sorting operating points

Für optimale Warm-Start-Effizienz die Betriebspunkte so sortieren dass benachbarte Zeilen physikalisch ähnliche Zustände beschreiben — z.B. Druck monoton steigend, Temperatur monoton steigend.

For best warm-start efficiency, sort operating points so that adjacent rows describe physically similar states — e.g., pressure monotonically rising, temperature monotonically rising.

Nicht-konvergierte Runs

Non-converged runs

Runs mit STATUS = FAILED haben in der Ausgabe für freie Variablen den letzten Solver-Zustand (nicht konvergiert). Diese Werte können unphysikalisch sein. Empfehlung: gefilterte Auswertung nur über CONVERGED-Zeilen.

Runs with STATUS = FAILED contain the last (non-converged) solver state for free variables. These values may be unphysical. Recommendation: filter analysis to CONVERGED rows only.

Ausgabedatei

Output file

result_batch.csv wird immer ins Arbeitsverzeichnis geschrieben (-DI Arbeitsverzeichnis = dort wo der java-Aufruf stattfindet). Bei wiederholten Runs wird die Datei überschrieben.

result_batch.csv is always written to the working directory (the directory the java invocation runs from). On repeated runs the file is overwritten.

Große Parameterstudien

Large parameter studies

Für sehr viele Betriebspunkte (N > 1000) empfiehlt sich -S:BROYDEN_SPARSE — Broyden mit GSPAR ist pro Run schneller als Newton weil die Jacobi nicht jede Iteration neu aufgebaut wird.

For very many operating points (N > 1000), -S:BROYDEN_SPARSE is recommended — Broyden with GSPAR is faster per run than Newton because the Jacobian is not rebuilt every iteration.

Parameterstudie vs. Optimierung: BatchRunner ist kein Optimierungsalgorithmus — er löst das Gleichungssystem für vorgegebene Eingabewerte. Für automatische Optimierung (z.B. Wirkungsgradmaximierung) muss ein externer Optimizer die CSV-Datei generieren und die Ausgabe auswerten.
Parameter study vs. optimization: BatchRunner is not an optimization algorithm — it solves the equation system for given input values. For automatic optimization (e.g., efficiency maximization) an external optimizer must generate the CSV file and evaluate the output.
